# lidx call graph against compilers

Generated by `benchmarks/oracle/run.py`. lidx `lidx 0.7.0`, built from main `8e3206a0b0` (2026-10-12). Method, toolchains and caveats: [README.md](../README.md).

Each cell is lidx's resolved CALLS edges graded against the answer a compiler gives for the same checkout, at the commits and scope repowise pins for the same cells. Intervals are 95% Wilson.

## Head-to-head with repowise

Every row grades lidx the way repowise grades its own tool, so the verdicts are neither flattered nor penalised by scope. Precision = lidx edges the compiler confirms / lidx edges the compiler can judge. Recall = compiler edges matched (dispatch edges included) / **all** in-scope compiler edges, capture gaps and unindexed callees charged to lidx: the denominator repowise uses. The scope differences handled here:

- **TypeScript**: repowise's `tsc` oracle emits no call made outside a function (module level) and withholds every call resolved to an abstract target (interface or type-literal member, abstract method, function-typed field), together with the function that makes it. The TypeScript rows drop the same edges from the denominator and leave those callers unjudged for precision. The stricter grading is in the diagnostic table below.
- **Rust**: repowise excludes test files by path only (`tests/` or `test/` directories) and keeps `#[cfg(test)]` code. The `path_tests_excluded` cell does the same. The `#[cfg(test)]`-excluded cell is in the diagnostic table.
- **Go**: unchanged; the cells already match (closure callees are keyed at the enclosing declaration here and at the literal in repowise, see the README).

### Counting rules in one place

- Oracle edges are distinct (caller declaration, callee declaration) pairs; lidx edges are deduplicated the same way.
- Callee outside the repository: not judged on either side.
- **Dispatch edges** (call through an interface or type-literal member, an abstract method, a function value, a trait method) are reported by the compiler as *possible* targets. They stay in the comparable recall; the static-recall column leaves them out.
- Oracle edge whose caller or callee is not a symbol lidx indexes (macro-generated Rust functions, nested functions): reported as a **capture gap** with its reason, out of the static recall, in the comparable recall denominator.
- lidx edge the compiler could not judge (caller file or function not in the analysed program, callee file not analysed, or a call site the compiler left unresolved): not counted for precision, listed under *ungradable*. The unresolved-site exclusion is the one that can flatter lidx; the per-cell lines below give precision if those pairs were counted wrong.

**How the rules were iterated.** The first samples found artefacts and mis-bucketed exclusions well above 10%; every item below was read by hand and led to a rule change before the final samples were drawn:

- Review of the first report (5 of 14 dispatch FNs mis-bucketed): TypeScript marked calls to a single-initialiser `const X = core.$constructor(...)` as dispatch (281 of 359 TypeScript dispatch edges), and Rust marked 449 inherent methods and 54 tuple-struct constructors as trait dispatch because the symbol was split on `/`. Both rules were rewritten and have unit tests.
- Bucket sample, Go `callee_file_not_covered`: 10 of 10 were production code resolved to a symbol in a `_test.go` file, an edge that cannot exist; the exclusion hid wrong edges. They are now counted as wrong edges (category `calls_test_code`). The same rule covers Rust and TypeScript. One further item was hidden behind a build tag although the oracle knew the site calls the standard library; sites the oracle knows call code outside the repo are now graded.
- Bucket sample, TypeScript `caller_not_judged`: 17 of 17 were mis-bucketed (export-list entries and shorthand properties at module level, class-field initialisers that only name a function, `export default function` callers). tsc analyses every call in a covered file, so the TypeScript oracle now judges every caller in the analysed files.
- Bucket sample, `oracle_unresolved_site`: 5 of 6 TypeScript items and 10 of 10 Rust items withheld an edge for a different call on the same line, or for an enum-variant constructor whose in-repo lookalike is a wrong edge. An unresolved call now withholds only a lidx edge whose callee has the same name; Rust variant constructor sites count as sites that call outside the repository.
- Bucket sample, Rust `callee_file_not_covered`: 2 of 2 were production code calling into `tests/`. Fixed with the `calls_test_code` rule.
- FP/FN samples before the final round: 3 of 20 TypeScript FPs were matching artefacts (calls from several module-level containers merged into one oracle edge that kept only the first container as an acceptable caller; `const objectKeys: ObjectConstructor["keys"]` resolved to lib.d.ts instead of the in-repo const; a local `const match = ... as Router["match"]` resolved to the interface member). A Rust edge to `SinkContext::bytes` was missing from the oracle because `#[cfg(test)]` on a struct field made the region detector swallow the next function; regions are now computed per gated item.
- Earlier rounds (first report): 9 of 20 Go FNs were dispatch fan-out and 5 of 20 TypeScript FNs had a nested callee lidx cannot index; Go range-over-func bodies, generic instances and unreachable "judgeable" callers, JSX, tagged templates, enum-variant constructors, merged declarations.

The final samples were drawn after all of the above: 120 FP/FN items and the exclusion-bucket items, none an artefact and none mis-bucketed. A rate of 0 over n items has a 95% Wilson upper bound of 3.84/(n+3.84); the report prints the interval per row and pooled. Caveats: (1) verdicts are one reader's judgement, with a note per item; (2) rare categories are unlikely to appear in a random sample of 10 to 20; (3) correct exclusions are judged against the source, but "unreachable from main" rests on RTA, which is sound for what it keeps and silent about code it never reaches.
