### Counting rules in one place

- Oracle edges are distinct (caller declaration, callee declaration) pairs; lidx edges are deduplicated the same way.
- Callee outside the repository: not judged on either side.
- **Dispatch edges** (interface method invocation, call of a function value, trait method) are reported by the compiler as *possible* targets. They are left out of the headline recall and shown as `recall incl. dispatch`; the repowise recall figures include them (their method note says so for syft), so compare against that column.
- Oracle edge whose caller or callee is not a symbol lidx indexes (macro-generated Rust functions, nested functions): reported as a **capture gap** with its reason, kept out of the recall denominator.
- lidx edge the compiler could not judge (caller file or function not in the analysed program, callee file not analysed, or a call site the compiler left unresolved): not counted for precision, listed under *ungradable*.

## Spot-check

20 random wrong edges (FP) and 20 random missed edges (FN) per language were read by hand against the source (sample: seed 412, cells go/cobra/tests, go/gitleaks/no_tests, go/syft/no_tests, ts/zod, ts/hono, rust/ripgrep, rust/fd). Verdicts: `lidx_error` (lidx is wrong or missed a real call), `oracle_artefact` (the compiler graph is not the right judge: dispatch fan-out, reflection, generated code, ...), `matching_artefact` (our matching rule mis-keyed a declaration).

**How the matching rule was iterated.** The first hand-read samples found artefacts well above 10%, so the oracle and matcher were changed and the samples redrawn:

- Go FN, first sample: 9 of 20 (45%) were dynamic-dispatch edges. RTA lists every possible target of an interface call or function-value call, so lidx missing one of them is not evidence of an error. Dispatch edges now leave the headline recall and get their own column.
- TypeScript FN, first sample: 5 of 20 (25%) had a callee that is a function nested inside another function. lidx indexes no such symbol, so the edge cannot exist in its graph. Callees lidx does not index now join the caller capture gap.
- Oracle bugs found while reading failures (not sampled): Go range-over-func loop bodies and generic instances were missing from the graph, and RTA reported unreachable functions as judgeable callers; TypeScript callees typed through an interface or function type, JSX components, tagged templates and parameters; Rust tuple-struct and enum-variant constructors, trait-method dispatch; interface and const of the same name treated as two declarations. All are fixed in the oracles or the matcher.

The final samples (this section) were drawn after those changes: 120 items, none an artefact. For 40 items per language a rate of 0 has a 95% Wilson upper bound of 8.8%, under the 10% bar. Two caveats on reading the table: (1) the sample is stratified only by random draw, so rare categories (e.g. the handful of Go closure-callee FPs) are unlikely to appear; (2) verdicts are one reader's judgement from the source at the call site, recorded with a note per item.

Categories that dominate each language drive the next fixes: see the per-cell FN/FP category lines above and `results/lists/`.
